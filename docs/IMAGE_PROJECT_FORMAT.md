# 原像素网格便携项目 1.0

2026-10-24。项目包核心与网页保存/打开入口、异步重新 Fiji 检查及网格重建已接通。**实际浏览器完整往返、大文件和崩溃恢复仍待验收**，此项目格式仅覆盖原像素网格，不代表整套 Fiji 的交互状态可保存。

## 内容

ZIP_STORED 包包含 `project.json` 和 `sources/0.bin` 等固定成员，最多八份源文件。清单严格拒绝未知字段，限定版本 `1.0` 与种类 `exact_pixel_grid`。每份来源含稳定键 s0…s7、原显示名、原字节数、SHA-256 和仅作记录的元数据；另有列数/间距、独立标注、原成品摘要。网格配方从实际生成的 GridProof 取得，不从外观猜测。

原始源文件完整保留，未把显示 PNG 或扁平化图替代原图。标注源 ID 转换为包内稳定键；同一项目重开后需重新映射到新会话 ID。原成品摘要是来源记录，后续若编码器或元数据策略改变，仍需分别核验像素与元数据，不凭容器摘要判断科学等价。

## 读取边界

压缩/加密方式、成员数、重复成员、总展开量、清单长度和成员尺寸均先检查，再创建全新暂存目录；总源字节不超过交互会话 2 GiB，单份不超过 1 GiB，清单不超过 256 KiB。输出路径不来自 ZIP 名称，只有原显示名中符合白名单的后缀用于未来读图器识别。逐块核对真实长度、摘要和 ZIP CRC，错误清理仅删除本次创建的已知文件；已有输出包或目标目录不被覆盖。

读取结果是 `PendingImageProject(verification_status=requires_fresh_inspection)`。清单中的 recorded_metadata 可以来自外部，不能直接装入 ImageAsset.metadata 或赋为 fiji_inspected。后续应用步骤必须重新调用受审 Fiji 检查器，核对真实像素/轴/尺度并重建网格，再验证并恢复标注。任一失败都应撤回导入结果并清理源图、产物和租约。

## 实际验证与待办

与网格、批量共 22 项测试通过：源 RGBA（含透明像素隐藏 RGB）原字节不变，配方重新生成像素相同，标注身份可重绑定；篡改源、路径越界、额外成员、未知字段被拒绝，失败不留下提取文件；旧包/目录不被覆盖；伪造的轴记录依旧是 pending 声明。

## 保存入口与资产事务

`GET /api/image/results/{id}/project` 先在成品锁内取得同一时点的配方与标注，再原子取得全部来源租约，流式写入项目内临时包。源图已删除返回 404，来源字节改变拒绝保存；导出期间源图不能移除，写完即释放租约。全局仅一份保存或下载占用名额，名额延续至响应结束，第二份返回 429；临时包不注册成常驻成品。响应正常结束、发送异常或取消均在 finally 中清理并释放名额，禁用提前交还临时路径的 path-send 扩展。参数和标注快照在导出后继续编辑不会改变已生成的包。此保存操作尚无队列取消按钮或进度。

`ImageAssetStore.stage_many` 先预约全部源图容量，逐块核对摘要，保持源图不可见，只有显式提交才发布；`adopt_many` 复用此事务。普通上传与导入共用数量/字节预约，失败与取消退还预约并只删除本次创建文件；已有资产不变。该内部方法本身不验证元数据真伪，调用方必须传入新 Fiji 检查所得元数据，不能使用项目清单的记录声明。事务退出后拒绝再次提交，导入进行中拒绝清理会话。

相关 30 项测试覆盖事务并发/取消、HTTP 实际响应包内容、源租约、下载准入、缺失/篡改来源和发送中断清理；前端 build 通过。尚未实际浏览器点击下载，测试文件规模不能证明 GiB 下载、崩溃恢复或全套格式保真。

## 异步重开与真实引擎证据

`POST /api/image/jobs/open-project` 在 multipart 解析前要求声明长度、按实际接收字节限制请求，和批量入口共用单份准入；项目请求限制为 2 GiB 加协议预算，原始来源和清单仍受各自较小的严格限制。准入持续到重开任务终态，避免与批量上传同时暂存。进入现有四项有界队列，逐源调用固定 Fiji 检查器（每份进程限时 180 秒），不将 recorded_metadata 传入检查器。全部源图经新检查后才进入事务暂存；用实际新 ID 重建原像素网格并重绑定标注。

发布锁顺序为任务管理器 → 资产 → 成品。成品大小和全部标注验证/写入先于成品可见，资产读写在伴随成品发布期间受锁保护；取消与提交在管理器锁中分界，提交成功后的取消不撤销已完成项目。排队取消、执行器拒绝、核验失败、容量不足、重建后取消或成品发布拒绝均有撤回测试。临时包、展开源和复制源可能同时存在；不是仅一份 2 GiB 磁盘占用，极大文件/磁盘紧张与进程崩溃仍待专门验证。

40 项相关测试通过，1 项真实引擎测试默认跳过；随后显式指向已审核的固定 Fiji 运行时单独执行该项，实际通过（14.31 秒）。两张带非等距 0.25/0.5 µm 标定的 16 位合成 TIFF 保存项目后，故意将包内记录尺度改成 999；新 Fiji 检查仍给出 0.25，重建两块逐样本等同独立 NumPy 数组，比例尺重绑定新资产 ID 后仍为 4 px。首次实测发现子检查 ID 加后缀不符合固定检查器 32 字符约束，修正为主任务和源索引派生的 32 位摘要后实际重跑通过。

HTTP 测试还覆盖重开期间第二项目和批量请求均返回 429、取消释放名额/文件、再次提交成功，以及已提交项目的取消保持成功。事务与请求测试中的检查器桩只用于故障控制，不能作为真实 Fiji 运行证据；上段显式运行测试才使用固定引擎。网页保存/打开按钮已接通且 build/lint 通过，尚未完成实际浏览器全流程验收。

## 实际浏览器往返与磁盘预检补充

同日使用本机前后端与已审核运行时，通过浏览器上传本次生成的 24×24 RGBA 合成图，生成网格、添加文字 A、实际下载 .bfsimg；移除本次图像和成品后通过网页重开下载包。任务由真实 Fiji 重新检查并完成，原文字 A 恢复，再追加 B。实际落盘 TIFF 用 NumPy 与原图逐样本比较一致，透明像素 (199,33,77,0) 的隐藏 RGB 不变；实际 SVG 含 A/B。JSON 原下载仅依赖 download 属性时没有落盘，新增明确附件响应的 annotations.json 后，再次重开、追加 B 和实际下载均成功。包内原始源字节与上传文件相同。摘要见 `IMAGE_PROJECT_BROWSER_EVIDENCE.json`；两次会话的下载分别记录，未混称同一成品 ID。

首次浏览器进入空会话发现真实崩溃：测量表单读取空的 selectedMeasureAsset，同时拼版控件重复。恢复表单条件和单份控件后，空会话/上传/重开均可操作；新增前端 SSR 渲染回归，防止空数据首次渲染再崩溃。窄窗口操作条允许换行，浏览器实测 351 px 视口的文档内容也是 351 px，无横向溢出；工作台状态点改用中性灰。批量文案改为容量限额，避免错误暗示收费。

项目解包前按实际清单总源字节，合计展开源、复制源及受支持网格的最坏四字节/像素输出；同一磁盘卷的写入相加，保留 64 MiB 余量。事务复制和项目导出前也检查各自写入空间。低空间测试证明在解包/启动 Fiji 前拒绝重开，导出拒绝后释放原图租约/准入并清理临时目录。该检查是可用空间预检，无法阻止其他程序随后占用磁盘；实际写入失败仍走异常撤回，不能宣称磁盘空间已被独占预约。

本轮 29 项 Python 专项通过、1 项真实运行时测试默认跳过，前端空会话渲染回归通过；本次浏览器使用真实引擎，另行作为运行证据。测试服务已停止，浏览器测试页已关闭。仍需更多格式、大文件/真实磁盘峰值、崩溃和重启恢复；其他 Fiji 操作的项目状态、栈/ROI/通道/时间状态与格式扩展仍属于完整目标。
